# Задача для ИИ-агента: добавить анимации появления элементов через GSAP без ломки существующего CSS-эффекта

## Контекст

На сайте уже используется анимация через библиотеку **GSAP**.

Также к блокам уже применено правило постепенной видимости:

```css
opacity: 0;
transform: translateY(30px) scale(0.98);
animation: reveal-in-view linear forwards;
animation-timeline: view();
animation-range: entry 10% entry 75%;
```

Этот эффект должен сохраниться.

Нужно дополнительно реализовать анимации появления:

- `.section-label` — появление сверху вниз;
- `.display-md.reveal-smooth` или элементы с классами `.display-md` и `.reveal-smooth` — появление слева направо.

---

## Цель

Добавить простые анимации появления через GSAP, не ломая существующую логику сайта и текущий CSS-эффект постепенной видимости блоков.

---

## Основные требования

1. Использовать уже подключённую библиотеку **GSAP**.
2. Не подключать новые библиотеки без необходимости.
3. Не менять файлы, которые не относятся к задаче.
4. Не усложнять код.
5. Избегать сложных вычислений, лишней логики и нестандартных решений.
6. Если можно написать проще — писать проще.
7. Если какие-то детали не указаны, агенту нужно самостоятельно додумать безопасную и минимальную реализацию.
8. Существующая анимация блоков с `reveal-in-view` должна продолжать работать.
9. Итоговый визуальный эффект должен быть согласован с текущим поведением сайта.

---

## Учёт существующего CSS-эффекта

К блокам уже применяется правило:

```css
opacity: 0;
transform: translateY(30px) scale(0.98);
animation: reveal-in-view linear forwards;
animation-timeline: view();
animation-range: entry 10% entry 75%;
```

Необходимо:

1. Проверить, не конфликтуют ли новые GSAP-анимации с этим правилом.
2. Если конфликт есть, скорректировать реализацию минимально.
3. Не удалять существующий эффект полностью.
4. Сохранить плавное появление блоков.
5. Если новые анимации применяются к тем же элементам, которые уже используют `reveal-in-view`, нужно избежать двойной или конфликтующей анимации.
6. Если нужно временно переопределить `opacity` или `transform`, сделать это только для нужных элементов и только в безопасной форме.
7. Если существующий CSS-эффект уже даёт нужное появление для части блоков, не нужно дублировать для них анимацию без необходимости.

---

## Требуемые анимации

### `.section-label`

Нужно сделать анимацию появления сверху вниз.

Ожидаемое поведение:

- элемент изначально скрыт или частично скрыт;
- при появлении смещается сверху вниз;
- постепенно становится видимым;
- анимация должна быть плавной и простой.

Допустимый смысл анимации:

- изменение прозрачности;
- вертикальное смещение.

---

### `.display-md.reveal-smooth`

Нужно сделать анимацию появления слева направо.

Ожидаемое поведение:

- элемент изначально скрыт или частично скрыт;
- при появлении смещается слева направо;
- постепенно становится видимым;
- анимация должна быть плавной и простой.

Допустимый смысл анимации:

- изменение прозрачности;
- горизонтальное смещение.

---

## Область применения

Нужно проверить, где находятся элементы:

- `.section-label`;
- `.display-md`;
- `.reveal-smooth`;
- блоки с текущим правилом `reveal-in-view`.

Если элементы с `.display-md.reveal-smooth` уже попадают под существующую CSS-анимацию, агент должен выбрать один из безопасных вариантов:

1. оставить существующий эффект и слегка дополнить его через GSAP;
2. отключить конфликтующую часть только для этих элементов;
3. применить GSAP только там, где это не ломает текущее поведение;
4. скорректировать классы или область анимации минимально.

Главное — текущий эффект постепенной видимости должен сохраниться.

---

## Ограничения по коду

Запрещается:

1. Писать сложную логику без необходимости.
2. Использовать тяжёлые вычисления.
3. Создавать лишние обёртки, хуки, утилиты или модули без необходимости.
4. Менять несвязанные файлы.
5. Полностью удалять существующую анимацию блоков.
6. Ломать текущее поведение `animation-timeline: view()`.
7. Дублировать анимации, если они вызывают конфликт.
8. Жёстко задавать сложные тайминги, если можно обойтись простой конфигурацией.

---

## Что нужно сделать агенту

1. Найти текущие места, где используется GSAP.
2. Найти элементы `.section-label`.
3. Найти элементы `.display-md.reveal-smooth`.
4. Найти блоки с существующим правилом `reveal-in-view`.
5. Определить, есть ли конфликты между CSS-анимацией и будущими GSAP-анимациями.
6. Реализовать простые анимации появления.
7. При необходимости минимально скорректировать стили или скрипты.
8. Убедиться, что существующий эффект постепенной видимости сохранён.
9. Проверить, что новые анимации не ломают старые.
10. Оставить максимально простое и чистое решение.

---

## Критерии приёмки

Задача считается выполненной, если:

1. `.section-label` появляется сверху вниз.
2. `.display-md.reveal-smooth` появляется слева направо.
3. Используется уже подключённый GSAP.
4. Существующий эффект блоков с `reveal-in-view` сохранён.
5. Нет конфликтов между CSS-анимацией и GSAP.
6. Нет изменений в файлах, которые не относятся к задаче.
7. Код простой и понятный.
8. Нет сложных вычислений и лишней логики.
9. Анимации работают плавно.
10. Поведение сайта не стало хуже до изменений.

---

## Приоритет

Если возникает выбор между:

- сложным решением;
- минимальным решением;
- сохранением текущего эффекта;

нужно выбирать:

> минимальное решение + сохранение текущего эффекта.
