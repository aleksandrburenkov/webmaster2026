# Контекст отладки (Debug) для DeepSeek-V4 Pro в Kilo Code

## Описание проблемы

В моем портфолио веб-разработчика принудительно срабатывают ограничения доступности операционной системы и браузеров. Если у пользователя включен режим «Уменьшение движения» (Reduce Motion), медиа-выражение `prefers-reduced-motion` и сторонние факторы полностью отключают все CSS Scroll-Driven Animations, Canvas-эффекты и трансформации. Из-за этого сайт выглядит статичным.

## Задача для ИИ-агента

Необходимо полностью, безвозвратно и превентивно исключить любое взаимодействие сайта с блокировками анимации от сторонних источников. Сайт должен принудительно воспроизводить 100% анимаций, переходов и эффектов скролла для ВСЕХ пользователей, полностью игнорируя системные настройки доступности ОС, браузера или сторонних плагинов.

Поскольку ты работаешь непосредственно в среде разработки (Workspace), выполни тотальное сканирование проекта по следующему алгоритму.

## Пошаговый алгоритм выполнения

### Шаг 1. Тотальное сквозное сканирование кодовой базы

1. Запусти глобальный поиск по всей директории проекта (все папки `core/`, `components/`, `interaction/`, `animation/` и т.д.) на предмет ключевого слова `prefers-reduced-motion`.
2. Проверь файлы всех типов: `.css`, `.scss`, `.js`, `.ts`, `.html`.

### Шаг 2. Очистка известных CSS-файлов

1. **В файле `premium-animations.css`** (строки ~279–291) полностью удали блок:
    ```css
    @media (prefers-reduced-motion: reduce) {
        .reveal,
        .reveal-fade,
        .reveal-scale,
        .reveal-smooth,
        .reveal-text,
        .reveal-aside-left {
            animation: none !important;
            opacity: 1 !important;
            transform: none !important;
            filter: none !important;
        }
    }
    ```
2. **В файле `core/reset.css`** удали закомментированный в конце блок стилей, содержащий `prefers-reduced-motion`, чтобы очистить код от мусора.
3. Если глобальный поиск обнаружит медиа-запрос `prefers-reduced-motion` в других CSS-файлах (например, в стилях компонентов `components/cards.css`, `components/buttons.css`), **немедленно удали эти блоки**. Основные анимации вне этих блоков должны остаться нетронутыми.

### Шаг 3. Превентивная проверка JavaScript и сторонних библиотек

1. Просканируй все JS-файлы на наличие метода `window.matchMedia('(prefers-reduced-motion: reduce)')`. Если такие проверки найдутся в скриптах интерфейса или инициализации библиотек, перепиши их так, чтобы они всегда принудительно возвращали `false` (например: `const prefersReduced = false;`).
2. Убедись, что при инициализации внешних библиотек (GSAP, AOS, Framer Motion или плагинов плавного скролла, если они будут подключены позже) отсутствуют конфигурационные свойства вроде `reduceMotion: true` или `respectPrefersReducedMotion: true`.

### Шаг 4. Проверка целостности (Верификация)

1. После удаления кода убедись, что синтаксис файлов не нарушен, все фигурные скобки `{}` корректно закрыты.
2. Убедись, что все анимации (`@keyframes`, Scroll-Driven эффекты, Canvas-логика в `HeroAnimation.js` и `FooterAnimation.js`) работают в полную силу и без задержек.

## Ожидаемый результат

Предоставь полный список файлов, где была обнаружена или вырезана логика блокировки анимации, и покажи финальные диффы (diff) изменений. В проекте не должно остаться ни одного упоминания `prefers-reduced-motion`.
